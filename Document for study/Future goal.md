# 设计不足

> Phase 1.3（2026-08-16）状态：以下五项已在不引入 LangChain、LangGraph 和 RAG 的情况下完成第一版实现。原始问题保留用于版本复盘。

1. [x] 目前针对于user_id，所有用户都设置为默认值，不能精确识别用户，所以后续需要添加ID生成，传递，存储等功能。
   - 实现：启动时输入 ID，校验后保存用户档案；每次启动创建并保存新会话。
2. [x] 目前对于大模型的router.py模块，目前里面的confidence变量一直固定为None，后续要大模型添加置信区间，判断目前的tool选择是否正确，如果较低，那么就需要让用户再重新表达下诉求，让诉求清晰明确。
   - 实现：计划和步骤均保存 0-1 置信度，低置信度或缺少前置状态时触发澄清；后续仍需用评测集校准阈值。
3. [x] 如果只是推荐旅游地，如果不涉及到城市的话，只涉及到省份的话，User Profile中不会发生变化，只是会保留以前的城市偏好。所以目前并没有能够实现综合上下文输出用户画像，现在仍然是以来每一次的运行，每一次对话，这样的话，有两个弊端，如果这次没提及，那么就仍然保持以前的信息，目前对于用户画像的构成角度太少，只保留了其中几个方面，综合不了上下文。另一个弊端是，如果这次对话涉及到了用户画像记录的信息，相当于这一次的对话有可能会完全覆盖上一次，导致每一次新对话占据100%的主导，这不合理。
   - 实现：长期 `UserProfile` 与本次 `TravelRequest` 分离，结合最近对话增量更新，并支持设置、合并、删除和清空；省级目的地可单独记录。
4. [x] 目前无法支持同时完成多个任务，每次对话只能选择一个工具，后面要能够满足多个工具调用。
   - 实现：`RoutePlan` 可以包含多个有序步骤，Executor 支持依赖检查和逐步状态回写。
5. [x] 在结果输出上面，新的结果会完全覆盖掉以前的结果。如果对于同一个人而言，可能会产生多轮对话，可能会调用多个工具，比如第一个tool是规划行程，第二个是做预算，这两次对话是连贯的，不应该直接覆盖，应该融合一下的。
   - 实现：每轮回答独立保存，同时生成完整方案的不可变版本与 `latest.md` 聚合快照。
